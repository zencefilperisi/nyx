# X.509 grammar notes (for the semantic layer)

The structure the semantic grammar layer (`grammar_x509.hpp`, Phase 2b) builds
and mutates. Simplified from RFC 5280.

```
Certificate  ::=  SEQUENCE  {
    tbsCertificate       TBSCertificate,
    signatureAlgorithm   AlgorithmIdentifier,
    signatureValue       BIT STRING  }

TBSCertificate  ::=  SEQUENCE  {
    version         [0]  EXPLICIT Version DEFAULT v1,
    serialNumber         CertificateSerialNumber,   -- INTEGER (can be large!)
    signature            AlgorithmIdentifier,
    issuer               Name,
    validity             Validity,
    subject              Name,
    subjectPublicKeyInfo SubjectPublicKeyInfo,
    ... extensions   [3]  EXPLICIT Extensions OPTIONAL }

Validity ::= SEQUENCE { notBefore Time, notAfter Time }
Time     ::= CHOICE { utcTime UTCTime, generalTime GeneralizedTime }

Extension ::= SEQUENCE {
    extnID      OBJECT IDENTIFIER,
    critical    BOOLEAN DEFAULT FALSE,
    extnValue   OCTET STRING }
```

## Bug-bearing shapes the semantic mutator should target

Historically these break real parsers, so the mutator deliberately produces them:

- **Serial number:** enormous INTEGER, negative, leading-zero non-minimal.
- **Validity dates:** boundary UTCTime/GeneralizedTime, `991231235959Z`,
  year-2000 pivots, malformed/short/overlong time strings, wrong CHOICE tag.
- **OIDs:** overlong arcs, non-minimal base-128, empty OID, huge sub-identifiers.
- **Extensions:** duplicated extnID, unknown critical extension, deeply nested
  OCTET STRING content, extension list far longer than expected.
- **Strings:** UTF8String / PrintableString with embedded NULs, invalid UTF-8,
  length/content mismatch.
- **Structure:** primitive where constructed is expected (and vice-versa),
  missing DEFAULT/OPTIONAL fields, extra trailing fields.

Each becomes a semantic-aware operator layered on top of the generic tree
mutator, so it stays valid DER while being maximally hostile to the parser.
